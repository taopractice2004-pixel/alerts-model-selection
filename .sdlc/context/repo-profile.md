# Repository Profile

- Repository mode: `MODE_C_EXISTING_PROJECT`
- Product: AlertService alert-management microservice
- Primary stack: .NET 8, ASP.NET Core Web API, EF Core 8, SQL Server, Serilog, Swagger
- Repository shape: `AlertService.sln` with six production projects and two xUnit test projects
- Shared build/runtime settings: `Directory.Build.props` enables `net8.0`, implicit usings, and nullable reference types; warnings are not errors

## Architecture

- Layering: HTTP controllers -> API service layer -> `IAlertRepository` -> provider-specific SQL/EF Core implementation
- Entry points / composition roots: `AlertService.API/Program.cs`; local launch profile is HTTPS on ports 7080/5080
- User-facing or external interfaces: JSON REST endpoints under `/api/alerts`, health probes under `/health/live` and `/health/ready`, development Swagger UI
- Business logic locations: `AlertService.API/Services/AlertManagementService.cs`
- Data / integration boundaries: `AlertService.Data/Interfaces/IAlertRepository.cs`; SQL Server implementation in `AlertService.Data.SQL`
- Runtime / infrastructure notes: Serilog request logging, exception middleware, DI, optional startup EF migrations, and SQL health checks

## Build And Run

- Install / restore dependencies: `dotnet tool restore`; `dotnet restore`
- Build / compile command: `dotnet build AlertService.sln`
- Test command: `dotnet test`
- Lint / format command: `NOT_CONFIGURED`
- Run main app locally: `dotnet run --project AlertService.API --launch-profile https`

## Data And Operations

- Primary data store: SQL Server through EF Core; migrations are in `AlertService.Data.SQL/Migrations`
- Environment/config notes: `ConnectionStrings:AlertDb` is required; development can apply migrations on startup; newer SDKs may need `DOTNET_ROLL_FORWARD=Major` for `net8.0`
- Operational assets: `database/01_CreateDatabase.sql`, `database/02_AlertServiceDb_Migrations.sql`, health endpoints, and file/console logging

## Testing

- Main test layers: API controller/service tests and SQL repository tests; API health-check integration tests use `WebApplicationFactory`
- Test frameworks: xUnit, Moq, ASP.NET Core MVC testing, EF Core InMemory and SQLite providers
