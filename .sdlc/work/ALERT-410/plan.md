## Summary
Add first-class alert tags so operators can assign, remove, and filter alerts by tag.

## Acceptance Criteria
| AC | Criterion |
|---|---|
| AC1 | Add a new Tag concept with a many-to-many relationship to Alert persisted via EF Core migration. |
| AC2 | POST /api/alerts/{id}/tags adds one or more tags with case-insensitive dedupe, max 10 tags per alert, and each tag length 1 to 30. |
| AC3 | DELETE /api/alerts/{id}/tags/{tag} removes a tag assignment and returns 404 when the alert or assignment does not exist. |
| AC4 | GET /api/alerts supports an optional tag filter that composes with existing filters. |
| AC5 | AlertResponse includes tags for each returned alert. |
