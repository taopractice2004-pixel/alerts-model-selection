## Summary
Operators can attach free-form tags to alerts, remove them, see them in `AlertResponse`, and filter `GET /api/alerts` by tag.

## Acceptance Criteria
| AC | Criterion |
|---|---|
| AC1 | A new Tag entity has a many-to-many relationship with Alert, backed by a new join table and EF migration. |
| AC2 | `POST /api/alerts/{id}/tags` adds one or more tags to the alert, deduplicating case-insensitively. |
| AC3 | An alert holds at most 10 tags and each tag is 1-30 characters; violations are rejected with 400. |
| AC4 | `DELETE /api/alerts/{id}/tags/{tag}` removes the tag from the alert; it returns 404 if the alert or the tag assignment does not exist. |
| AC5 | `GET /api/alerts` accepts an optional `tag` filter that composes with isActive, severity, date range, and search. |
| AC6 | `AlertResponse` includes the alert's tags. |

## Boundaries & Assumptions
- Primary slice: Alert tagging across AlertService.API controller/service, DTO, Models, Data, and Data.SQL.
- Out of scope: tag management endpoints; orphaned Tag cleanup; tags on create/update requests; README and `.http` updates; tags in the summary endpoint.
- Assumptions to confirm:
  - POST body is `{ "tags": ["a", "b"] }`.
  - Tags are trimmed; uniqueness and matching are case-insensitive for add, remove, and filter.
  - Re-adding a tag already on the alert is a no-op, not an error.
  - A request that would push an alert past 10 tags is rejected whole with 400, and nothing is added.
  - The tag filter is an exact case-insensitive match on one tag name.
  - Migration files are hand-authored to match EF output because `dotnet ef` cannot be run in this stage.
  - Tag rows are not deleted when their last alert assignment is removed.

## Risks
- Medium: schema migration plus Include on the list query; rollback = revert the commit and apply the Down migration.
- Low: two concurrent requests creating the same new tag can hit the unique index and return 500.
- Low: positional `GetAllAsync` callers could mis-bind if `tag` is not placed last before `cancellationToken`.
